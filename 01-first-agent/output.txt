################################ WHY thinking={"type": "disabled"} IS IN loop_by_hand.py ################################
# First version of the script (no thinking line, max_tokens=1024), normal mode, 26 Nov ~11:25 IST:
#   qwen3.5:4b is a thinking model and Ollama lets it think by default. A1001: 10/10 correct, 3.7-5.7 s per run.
#   But in 3 of 12 runs of other questions (4 questions x 3) the model kept thinking until it hit max_tokens (stop_reason max_tokens,
#   about 25 s, no answer): "Hi, this is Liam..." 2 of 3 runs, "Where is my order A9999?" 1 of 3 runs.
#   Our loop handled it honestly ("Stopped early: max_tokens"), but a beginner needs it to work.
# Side test, same question 5 times each: thinking disabled -> 5/5 tool_use, 31 output tokens, 0.8-1.5 s;
#   thinking on with max_tokens 4096 -> 5/5 tool_use but 75-549 output tokens, 2.4-14.2 s.
# Decision: thinking={"type": "disabled"} with the comment "Ollama only". For Claude, leave the line out:
#   current Claude models (e.g. Claude Opus 5.5) reject {"type": "disabled"} and decide on thinking themselves.
# Example of the old behaviour (first version):
#   $ uv run loop_by_hand.py "Hi, this is Liam. What is in my order A1002 and when does it arrive?"
#   turn 0: max_tokens (26.0 s)
#   Answer: Stopped early: max_tokens
